Proyecto Integrador: App Gastos Hormiga
Guía de Requerimientos - Segundo Avance (Funcionalidad e Interactividad)
Este segundo hito tiene como objetivo transformar la interfaz estática en una aplicación funcional. Se evaluará la gestión de estados, el flujo de datos entre componentes y la capacidad de navegación en el cliente.
Conceptos Clave a Desarrollar
• Gestión de Estado (useState): Control de formularios y persistencia de la sesión de usuario.
• Comunicación entre Componentes (Props): Flujo de información y funciones entre
componentes.
• Navegación Dinámica: Implementación de rutas para moverse entre las vistas del aplicativo.
• Lógica de Acceso: Restricción de vistas privadas basada en el estado de autenticación local.
Historias de Usuario (HUs)
HU05 - Registro de Usuario
Como nuevo usuario, quiero ingresar mis datos personales para que la aplicación cree mi perfil y me reconozca.
• Criterio de aceptación: El formulario debe capturar nombres, tipoDocumento, documento y edad.
• Técnico: Los datos deben guardarse en un estado o localStorage para simular la persistencia. HU06 - Inicio de Sesión
Como usuario registrado, quiero ingresar con mi número de documento para acceder a mi información personal.
• Criterio de aceptación: Validar que el documento coincida con un usuario existente. Si tiene éxito, habilitar el acceso a las áreas privadas.

Estándares de Desarrollo
1. Arquitectura de Datos: Es obligatorio usar la carpeta services/ para gestionar los datos
simulados (Mocks).
2. Componentes Funcionales: Uso estricto de React Hooks.
3. Validaciones: Los formularios no deben procesar datos vacíos. Se debe mostrar feedback
visual en caso de error.
Proyección a Momento 3 (Escalabilidad)
Para asegurar que este trabajo sea útil en la siguiente etapa (Consumo de API real), el equipo debe:
• Centralizar los Datos: No "quemar" datos directamente en los componentes. Todo debe
venir de las funciones definidas en services/.
• Respetar el Modelo del Back: Usar exactamente los nombres de atributos definidos en el
PDF de Backend.
• Preparar el Estado: Estructurar los estados de tal forma que en el próximo hito solo sea
necesario añadir el hook useEffect para reemplazar los datos locales por llamadas asíncronas.
